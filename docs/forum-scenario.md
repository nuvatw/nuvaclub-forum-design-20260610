# nuvaClub 論壇情境說明

這份說明用來讓閱讀者快速理解 nuvaClub 論壇的核心情境，以及目前 UI/UX mock 想呈現的互動重點。

## 論壇定位

nuvaClub 論壇是會員在學習與實作過程中留下紀錄、提出問題、展示階段成果的地方。使用者不需要先完成大型成果才可以發表；只要有值得記錄、討論或驗證的內容，就可以在論壇裡發佈。

論壇目前以三種內容類型組織資訊：

- `貼文`: 分享學習心得、AI 工作流、活動筆記、工具連結或日常觀察。
- `問問題`: 描述課程問題、AI 系統製作卡關點、已嘗試的方法，以及希望他人協助判斷的部分。
- `里程碑`: 放上 prototype、截圖、連結或練習成果，讓他人看見目前做到哪一步。

## 發佈情境

使用者按下論壇的發佈入口後，可以選擇 `貼文`、`問問題`、`里程碑`。

`貼文` 適合比較輕量的分享，例如看到一個 AI 學習資源、整理了一段 prompt 經驗，或想記錄今天的學習流程。

`問問題` 適合需要他人協助判斷的情境。使用者可以補充自己正在處理的課程、單元、資料狀態、已嘗試方法，讓回覆者更容易理解問題。

`里程碑` 適合把階段成果放出來。它可以是一個可點擊的 prototype、一張截圖、一段操作說明，或一個想驗證的流程。重點是讓成果被看見，並能收到回饋。

## 瀏覽與互動

閱讀者可以依照內容類型篩選，只看 `貼文`、`問問題` 或 `里程碑`。也可以依時間範圍與互動數排序，快速找到近期討論、尚未被充分回應的問題，或社群正在關注的里程碑。

每篇內容都保留基本互動：愛心、留言、分享、收藏。這些互動讓論壇不只是公告牆，而是會員之間互相補充、回饋與累積脈絡的地方。

## UI/UX 呈現重點

目前的 mock 以可掃讀的論壇 feed 為主：上方有發佈入口，中段有搜尋、類型篩選、時間篩選與排序，右側欄顯示熱門標籤與里程碑焦點。

發佈 modal 讓三種內容類型並排呈現。`里程碑` 類型旁有 `什麼是里程碑？` 的提示入口，可開啟說明影片，幫助使用者理解這個類型適合放什麼。

里程碑卡片保留 preview 區塊，讓 prototype、截圖或 demo 的感覺比一般文字貼文更明確。這個視覺差異是為了讓閱讀者一眼看出它是一個階段成果，而不是一般討論。

## GitHub 呈現重點

這個 repo 是獨立的前端 UI/UX prototype，資料全部來自 mock data。它用來對齊論壇閱讀、篩選、排序、發佈與里程碑說明的體驗，不代表正式後端資料結構已完成。

開發者閱讀時，可以先看 `README.md` 了解功能範圍，再進入 `src/app.js` 查看 mock data、內容類型與互動狀態，最後用 `src/styles.css` 查看版面與響應式處理。
